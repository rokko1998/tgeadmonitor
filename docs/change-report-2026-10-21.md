# Внедрение семантической проверки, 21.10.2026

## Что изменилось

Вместо уведомлений по сумме regex-баллов работает цепочка: сохранение сообщения → бесплатные отсечения → постоянная очередь → Jev → проверка типизированных ответов → атомарная запись решения и карточки в очередь отправки. Старая оценка не включается при ошибке API или исчерпании денег.

Один запрос Jev оценивает пять аспектов сообщения: роль автора, предмет запроса, достаточность деталей, операцию и соответствие бизнес-политике. Код требует согласованных свидетельств прямой покупки; для непрямых учитывает строительный контекст и согласованные исключения. Полный ответ, модель, версия вопросов, токены и стоимость сохраняются в SQLite. Значения вероятностей Jev — свидетельства модели, а не измеренная гарантия правильности.

Прямые материалы: чёрный металлопрокат, строительные пиломатериалы. Прямые услуги: обработка и изготовление из металла. Смежные строительные запросы могут быть непрямыми; контакт не объявляется покупателем трубы без явного запроса. Согласованные вручную 23 проекта определяют границы: подробные строительные подряды допускаются, общие вакансии/демонтаж/бытовые подработки не превращаются в лиды из-за цены или названия профессии.

Непрямые карточки приходят сразу с отдельной пометкой. В 21:00 МСК — сводка за период между вечерними границами, без повторных проектов и отклонённых оператором записей. `/indirect` показывает последние 24 часа. Сводка использует выдержки из оригиналов и не тратит Jev.

## Очистка и источники

Список чатов и состояния находятся в SQLite. Удалены YAML-списки, их резервные и сгенерированные копии, старый генератор вступлений, скоринг, прежняя нечёткая дедупликация и зависимость rapidfuzz, устаревшие тесты старого классификатора, файлы IDE и случайные текстовые артефакты. Одноразовый JSON-набор позволяет мигрировать старые источники и запускать новую БД; он не переопределяет её на каждом старте. Исторические таблицы и данные не удаляются.

Добавление чатов работает пачкой по ссылкам и @именам, включая приватные приглашения и ожидание одобрения. Ручные паузы не сбрасываются при перезапуске или обновлении метаданных. `/pause` оставляет приём и хранение сообщений, но выключает платную оценку; `/resume` возвращает оценку новых сообщений. `/keep` защищает важный источник.

Автопауза мягкая: 30 дней наблюдения, 1000 уникальных сообщений за последние 30 дней, отсутствие прямых/непрямых возможностей, отсутствие неразобранной очереди. Простои контейнера не считаются наблюдением. При паузе сообщения продолжают сохраняться; причина отправляется оператору. Измеренный размер БД около 234 МБ, свободно около 23 ГБ; оснований отключать архив на паузе сейчас нет.

Историческая загрузка `src.tools.backfill` теперь только архивирует. Она не отправляет старые сообщения в платную очередь и не рассылает старые лиды. Старые ожидающие карточки по баллам при первой миграции помечаются superseded.

Подробный `/help` объясняет карточки, кнопки обратной связи, добавление чатов, ID, паузы, автопаузу, дайджест и расходы. Команды появились в меню. Учтён фактический групповой OWNER_CHAT_ID: управление доступно администраторам этой группы; простого членства недостаточно.

Полный запрос участвует в ключе кэша; смена модели/вопросов/политики не использует старое решение. У других приложений с тем же ключом собственные расходы; локальный ledger не является балансом аккаунта провайдера.

Приложение и тесты локально не запускались. На UK-сервере в отдельном контейнере без сети, production-тома и секретов прошли **165 тестов**. Включены 72 исходных целевых запроса для проверки полноты бесплатного фильтра, 14 новых положительных примеров владельца, 27 сохранённых ответов Jev с итоговыми классами, добавление пачек ссылок и @имён, недоступный API, ошибки схемы, лимиты и резервы, кэш, дубли, откат записи при сбое, архив на паузе, восстановление очереди и границы вечерней сводки.

На отдельной серверной копии настоящей БД прошла миграция и integrity_check: **222612 сообщений, 27 лидов, 27 уведомлений** сохранены; старые сообщения не поставлены в Jev. Перед выкладкой создана согласованная SQLite-резервная копия `/var/backups/tgeadmonitor/pre-semantic-20261021T110411Z.sqlite`, прежний образ сохранён как `tgeadmonitor-rollback:c8ef064`.

Набор вручную разобранных примеров мал и использовался для настройки правил: совпадение на нём не означает такую же точность на будущих сообщениях. Дальнейшее уточнение — по сохранённым решениям и кнопкам «Полезно / Мусор», с явным изменением версии политики.

## Проверка после первого деплоя и уточнение заявок

Коммит c50d78f успешно развернулся Dokploy. В новом production-образе повторно прошли 165 тестов; конфигурация TypeSafe/jev-1.14.0/$4/21:00 применена, перезапусков контейнера из-за ошибок не было. Четыре реальных API-запроса проверили прямой запрос, сантехнический непрямой контакт, короткое C и заказ кухни; пятая проверка рекламы персонала прошла без API. Все пять классов совпали с ожидаемыми. Стоимость $0.000532686 учтена в production-ledger. Две карточки сформированы в отдельной временной БД, тестовая рассылка в Telegram не выполнялась. API бота подтвердил меню команд, отключённый privacy mode и доступ администратора рабочей группы к управлению.

Финальные уточнения покрыты **172 серверными тестами**: приватная заявка переживает закрытие/повторное открытие БД и после одобрения активирует источник с ID, названием и @именем; публичная заявка проверяет членство без повторного JoinChannelRequest. Если API ещё не подтверждает членство, источник остаётся ожидающим, а не включается преждевременно.

Планирование выполняет постоянная очередь source_requests с next_attempt_at: проверка через 300 секунд, далее каждые пять минут до принятия или ошибки приглашения. Системный cron вне контейнера не требуется. Ограничение FloodWait сдвигает проверку на разрешённый Telegram срок. Данные и ближайшее время проверки остаются в томе БД при деплоях.

Дополнительно восстановлен при миграции и сохраняется в БД признак автовступления для 14 ранее согласованных адресов. Ручная пауза блокирует автовступление при перезапуске; обновление метаданных не снимает её. Миграция проверена на копии настоящей БД с сохранением истории и integrity_check=ok.

Проверка доступности обнаружила старые источники, для которых у аккаунта нет членства либо недостаточно данных для разрешения прежнего ID. Поэтому /chats теперь различает фактическое подключение, архивный режим, отключение и недоступность; такие записи не выдаются за работающий мониторинг. Для восстановления недоступных по прежнему ID приватных чатов нужна действующая ссылка-приглашение. Чужое название не подставляется вместо отсутствующей ссылки.
