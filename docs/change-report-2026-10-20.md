Другой обнаруженный беспорядок: в `locations.yaml` находился текст конфигурации скоринга; три идентификатора услуг повторялись в `products.yaml`; регрессионный тест ссылался на отсутствующий датасет и неверный корень проекта. В истории также есть старые резервные конфиги, файлы IDE и устаревший стартовый датасет с описанием в имени — они сохранены, чтобы не смешивать задачу с удалением исторических материалов.

## Принятые владельцем решения

- Основа — feature, результат — main, автодеплой через Dokploy.
- Одно сообщение владельца с одной или несколькими ссылками добавляет источники без дополнительных вопросов.
- Приватные приглашения поддерживаются; ожидание одобрения отделено от успешного вступления.
- Все регионы, без географического ограничения.
- Короткие запросы без деталей — C, без уведомлений.
- C сохраняется в БД; композитная арматура игнорируется; смешанный запрос арматуры и цемента остаётся лидом по арматуре.
- Пиломатериалы и услуги сохраняются. Примеры нового документа имеют приоритет.
- Внести явные адреса из списка групп, остальные названия перечислить отдельно без самостоятельного поиска совпадений.
- После прямого запрета владельца локально не запускать приложение, тесты и контейнеры. Функциональную проверку после деплоя выполняет владелец.

## Добавление источников

Вместо пошагового мастера реализован приём ссылок непосредственно в личном диалоге владельца с ботом. `/addchat` остаётся необязательным способом ввода. Поддерживаются публичные адреса, @username, приглашения, ссылки на сообщения публичных чатов и скрытые под текстом ссылки Telegram. Адреса нормализуются; регистр публичного username не создаёт дубль, регистр приватного токена сохраняется.

Каждый адрес сначала сохраняется в новой таблице `source_requests`, затем обрабатывается последовательно фоновым обработчиком. Polling бота и основной мониторинг при этом продолжаются. Ошибки одной ссылки не отменяют другие; каждый адрес получает свой результат. Новые неизвестные источники получают тип `unclassified`, без геофильтра; метаданные уже известных чатов сохраняются. Отключённые в конфигурации источники не включаются молча.

Публичный чат считается добавленным только после подтверждения участия аккаунта. Ошибки вступления больше не подавляются. Ссылки на пользователей/ботов отклоняются. Для приватных приглашений обработаны устаревшие/недействительные ссылки, существующее участие и разные формы ответа Telethon (`chats` и вложенные `updates.chats`).

Заявки на одобрение сохраняются и проверяются примерно каждые пять минут без повторной отправки заявки. FloodWait приостанавливает всю очередь на срок Telegram; ожидание сохраняется в БД и учитывается после перезапуска. Сетевые ошибки повторяются автоматически. Между запросами очереди предусмотрена пауза.

Динамические источники восстанавливаются из БД после рестарта. На старте загружаются диалоги для восстановления access hash приватных чатов при использовании StringSession; недоступные из-за временной ошибки источники проверяются повторно. Пустой список доступных источников больше не завершает сервис: бот продолжает принимать ссылки. Добавлена команда `/chats`, `/help` объясняет новый ввод.

## Обновление правил

Источник правил: https://docs.google.com/document/d/1y2bGnwFvjvkPxV_ZybSnf9BDOWn59yUReh34ZBFBrnM/edit

Документ прочитан через текстовый экспорт; все 120 примеров перенесены в `data/dataset.jsonl`. Ожидаемая разметка после уточнений владельца: 72 `lead`, 15 `potential`, 33 `ignore`. Это ожидаемые классы, а не измеренная точность классификатора.

В `qualification.yaml` вынесены правила неоднозначных товаров, коротких запросов и строительных потребностей C. Примеры «Нужна арматура», «Куплю металл», «Нужна труба», «Нужен лист, 30 штук», «Нужен профнастил» сохраняются как C. Запросы на забор, навес, теплицу и подобные работы из документа не дают уведомлений. Проектные признаки сохраняются для анализа, но сами не создают основной поток уведомлений.

Расширены запросы о цене в чат-стиле, вежливые запросы прайса, «привезите/доставьте», распознавание евроштакетника, металлических столбов, профтрубы с двумя размерами и листа г/к. Добавлены количество карт/секций/квадратных метров и марки профнастила. Продавцы и реклама имеют приоритет отрицательных правил; запрос прайса покупателем больше не считается предложением продавца только из-за слова «прайс».

Нецелевые значения (композитная арматура, пластиковые трубы, спортивная/москитная/затеняющая сетка, бумажный лист, «уголок для отдыха») исключаются из сопоставления товаров. При смешанной покупке сохраняются распознанные целевые материалы. Отдельно исключены явно размеченные вакансии, поиск работы, лом, покупка недвижимости и прочистка канализационной трубы.

Геофильтр удалён из обработки сообщений, включая федеральные источники. Список городов восстановлен как справочные метаданные; ошибочное отсутствие ключа `locations` теперь выдаёт понятную ошибку конфигурации. Повторяющиеся определения услуг объединены с сохранением шаблонов, добавлена проверка уникальности ID товаров.

Полный список адресов, названий без ссылок и двух ботов-посредников: [sources.md](sources.md). Боты-посредники не считаются чатами; для них нужен ручной доступ и прямая ссылка на целевую группу. Google-документы использованы как снимок требований; автоматическая синхронизация будущих правок документов не добавлялась.

## Данные и Dokploy

Dockerfile, Compose и название постоянного тома не изменялись. Новые зависимости и новые обязательные переменные окружения не добавлялись. Из feature перенесены её дополнительные колонки БД с аддитивной миграцией; текущая работа добавляет таблицу очереди. Удаления таблиц, очистки сообщений или перезаписи существующего тома нет.

Ранее сохранённые сообщения не пересчитываются по новым правилам автоматически. История и старые статусы остаются в БД. Новые правила применяются к новым сообщениям. История чатов при добавлении автоматически не сканируется; существующий инструмент backfill сохранён, но не запускался.

## Проверка и ограничения

До сообщения владельца о запрете запуска были начаты две исходные проверки `pytest` в отдельных временных копиях main и feature. Обе завершились ошибкой сбора тестов: отсутствовал `src/data/dataset.jsonl`. Тесты классификации тогда не выполнились; приложение, контейнеры и подключение к Telegram не запускались. После запрета pytest не повторялся.

Для итоговых изменений выполняется только статическая проверка: разбор синтаксиса Python без импорта модулей проекта, чтение YAML/JSON, компиляция регулярных выражений и просмотр diff. Подготовлены регрессионный корпус из 120 сообщений и автономные тесты разбора ссылок, доступа владельца, сохранения очереди, ошибок вступления, отказа для ботов и ожидания одобрения. Они не запускались.

Итог статической проверки: синтаксис 26 Python-файлов, 13 YAML-файлов и 482 регулярных выражений разобран без ошибок; 52 ID товарных категорий уникальны; корпус содержит 120 корректных JSON-строк с согласованными ожидаемыми классами. `git diff --check` не выявил ошибок форматирования diff. Пути к корню проекта и эталонному датасету проверены чтением файлов.

Эта проверка не подтверждает фактический запуск сервиса, успешность миграции на серверной БД, доступность перечисленных Telegram-групп, доставку уведомлений или успешность деплоя Dokploy. Эти пункты требуют серверной проверки владельцем. Для начала подходят сценарии из [README.md](../README.md): `/help`, `/chats`, пачка ссылок, повтор адреса, ошибочное приглашение, лид из нового чата, C без уведомления и сохранение источника после перезапуска.

При реализации формы ответов и восстановления сущностей сверены с документацией и установленными исходниками Telethon. Справка API: [вступление в публичный чат](https://core.telegram.org/method/channels.joinChannel), [импорт приватного приглашения](https://core.telegram.org/method/messages.importChatInvite), [сущности и access hash](https://docs.telethon.dev/en/stable/concepts/entities.html).
