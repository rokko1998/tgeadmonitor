# Telegram Lead Monitor

Монитор читает Telegram-чаты через аккаунт Telethon, сохраняет сообщения в SQLite и отправляет оператору карточки через бота. Очевидный мусор отсеивается регулярными выражениями до платного API. Остальные кандидаты проходят Jev: пять независимых вопросов в одном запросе, итоговые ограничения применяет код.

## Как пользоваться

Отправьте боту одну или несколько ссылок либо @имён:

```text
@example_chat
https://t.me/another_chat
https://t.me/+invite_hash
```

Команда `/addchat` необязательна. Принимаются публичные адреса, ссылки на сообщения публичных чатов, приватные приглашения, `tg://join` и `tg://resolve`. Результат приходит по каждому адресу; ошибка одной ссылки не отменяет остальные. Если требуется одобрение, сохраняется отложенная задача с ближайшим временем проверки: каждые пять минут бот проверяет членство без повторной подачи заявки, а после принятия записывает ID, имя и @адрес источника и включает мониторинг. Задача переживает перезапуски Dokploy. Вступление, ожидание одобрения и ограничения Telegram обрабатываются постоянной очередью без системных crontab-файлов.

Полная инструкция и примеры находятся в `/help`; команды также зарегистрированы в меню бота. Управление доступно владельцу личного диалога либо администраторам настроенной группы `OWNER_CHAT_ID`. Для сообщений со ссылками без команды в группе бот должен получать обычные сообщения: сделайте его администратором или отключите privacy mode через BotFather. Команды `/addchat ...` доступны и при privacy mode.

- `/chats` — источники, числовые ID, режим, качество и фактическая доступность аккаунту; неподключённые записи не отображаются как работающий мониторинг.
- `/pause ID`, `/resume ID` — выключить/вернуть оценку Jev. На паузе сообщения сохраняются в архив, карточки не отправляются. Архив за паузу при возобновлении не рассылается.
- `/keep ID`, `/unkeep ID` — защита важного чата от автопаузы.
- `/indirect` или `/digest` — непрямые возможности за 24 часа.
- `/jev` — расход с резервами, месячный лимит и очередь; `/jevretry` — повтор ошибок после исправления API/ключа.
- `/stats`, `/stats7`, `/stats30` — аналитика за всё время, неделю, месяц.
- `/month` — отчёт за текущий календарный месяц на данный момент; `/month 2026-10` — за указанный месяц.

**Ежемесячный отчёт** автоматически приходит 1-го числа в **09:00 МСК** за предыдущий календарный месяц. В нём: сколько сообщений прошло обработку и из скольких чатов, сколько сохранено только в архив, сколько найдено прямых/непрямых лидов без повторных карточек и сколько потрачено на Jev. Отклонённые оператором лиды показаны отдельно внутри найденных. Обработка включает бесплатные фильтры; архив за паузу/импорт истории учитывается отдельно. Сообщения считаются по времени сохранения, лиды — по времени обнаружения, расходы — по месяцу журнала запросов МСК. Неподтверждённые резервы не выдаются за фактическую стоимость.

Отчёт формируется из SQLite без вызовов Jev. Снимок чисел и отправка сохраняются вместе; перезапуск не создаёт повторный отчёт, а пропущенные месяцы после возобновления работы формируются по очереди. При недоступности Telegram месячная отправка повторяется с увеличением интервала до часа, без ограничения в 50 попыток. Автоматическая серия начинается с месяца включения функции. `/month` для уже сформированного периода повторно показывает сохранённый отчёт. При необходимости время меняется необязательной переменной `MONTHLY_REPORT_HOUR_MSK` (по умолчанию `9`); добавлять её в текущий env не требуется.

## Отбор и хранение решений

**Прямой лид** — текущий пригодный к обработке запрос на металлопрокат, строительные пиломатериалы, изготовление или обработку металла. Требуется согласованность ответов Jev о намерении, предмете, операции и деталях запроса. География не ограничена.

**Непрямой лид** — полезный строительный контакт без заявленной покупки наших материалов. Уведомление приходит сразу с соответствующей пометкой. В **21:00 МСК** отправляется сводка без повторов; период идёт от предыдущей вечерней границы до текущей, сообщения после 21:00 попадут в следующую. Дайджест строится из сохранённых сообщений без нового вызова Jev. Пропущенный при перезапуске период включается в ближайшую сводку.

Короткие «Нужна арматура», «Куплю металл», «Нужна труба», «Нужен лист, 30 штук», «Нужен профнастил» — `potential` (C), без рассылки. Реклама персонала и заказ кухни с упоминанием вытяжки — мусор. Поиск сантехника для подключения унитаза — непрямой контакт. Детальные строительные проекты могут быть непрямыми даже при поиске исполнителей; общие вакансии, демонтаж и бытовые подработки сами по себе не подходят. Истёкшие явно указанные сроки подачи заявок отсекаются до API.

Статусы: `direct`, `indirect`, `potential`, `ignore`, `review`; неопределённые `review` сохраняются без карточки. В SQLite находятся исходные сообщения, полные типизированные ответы Jev, версия/хеш вопросов и политики, модель, токены, стоимость, решения по каждому сообщению, связи дублей и обратная связь «Полезно / Мусор». Эта обратная связь не меняет промпт автоматически. Дубликаты содержательных проектов с одинаковым текстом и отличиями только в контактах не вызывают повторную карточку в течение семи дней. Независимые короткие запросы разных авторов не объединяются.

Правила Jev — `config/jev_questions.json`, композиция — `src/processing/semantic_policy.py`, бесплатный фильтр — `src/processing/prefilter.py`. YAML-словари товаров/географии используются для извлечения данных карточки и не разрешают рассылку по баллам. Старый классификатор с баллами удалён.

## Источники и автопауза

**SQLite — единственный рабочий источник списка чатов и их состояния.** YAML-списки и старые генераторы удалены. `src/storage/source_seed.json` — одноразовый исторический набор для новой/мигрирующей БД; после отметки миграции он не применяется. Существующие источники, ручные паузы и новые чаты сохраняются между деплоями. Таблицы истории не удаляются.

По умолчанию чат переводится в архивный режим после **30 дней фактического наблюдения и 1000 уникальных сообщений за последние 30 дней**, если нет прямых/непрямых возможностей и неразобранной очереди. Время простоя контейнера не засчитывается как наблюдение. Ошибки API, исчерпанный бюджет и сомнительные решения препятствуют автопаузе, пока находятся в рассматриваемом периоде. Бот сообщает причину; `/resume` возвращает оценку, `/keep` защищает от будущей автопаузы. Новые сообщения при паузе остаются в БД. На момент внедрения БД занимала около 234 МБ при примерно 23 ГБ свободного места на сервере.

Адреса групп из документа и список недостающих ссылок: [docs/sources.md](docs/sources.md).

## Env и Dokploy

Список переменных без секретов — [.env.example](.env.example). Основной провайдер — **TypeSafe**, модель закреплена как `jev-1.14.0`. API: `https://api.typesafe.ai/v1/systemone`, ключ `JEV_API_KEY`. Альтернативный адаптер B.AI поддерживает закреплённый `jev-1.13.0`; модель и ключ должны соответствовать провайдеру.

`JEV_MONTHLY_BUDGET_USD=4` ограничивает расходы **этого приложения** за календарный месяц по Москве. До запроса резервируется консервативная оценка; после ответа сохраняется фактическое число входных токенов по тарифу $0.042/млн, вывод бесплатный. При неизвестном результате сети резерв сохраняется. Общие расходы других приложений с тем же ключом сюда не входят. Изменение тарифов требует обновления расчёта. При недоступности API или исчерпании лимита сообщения ждут в БД; старый скоринг не подменяет Jev. Кэш зависит от провайдера, модели, полного текста, вопросов и версии политики.

Пуш в `main` запускает существующий Dokploy CI/CD. Именованный том `lead-monitor-data:/app/data` обязателен: в нём история, очередь, бюджет, источники и сессия. Миграции добавляют таблицы/колонки к существующей БД. Старые неотправленные уведомления по баллам помечаются `superseded`; старые сообщения автоматически не отправляются на платную переоценку.

## Проверка и инструменты

Приложение и тесты локально не запускаются по указанию владельца. Тесты выполняются на UK-сервере в изолированном контейнере без сети, секретов и production-тома:

```text
python -m pytest -p no:cacheprovider -q tests
```

`data/semantic_reviewed.jsonl` содержит 23 согласованных примера с удалёнными телефонами. `data/semantic_answers_reviewed.jsonl` — сохранённые ответы Jev для 27 согласованных проверок; тестируется как схема ответа, так и итоговая композиция решений. Это регрессионные проверки, а не независимая оценка качества на будущих чатах. `data/dataset.jsonl` хранит исходные 120 примеров документа; прежние классы услуг в нём исторические, новые договорённости имеют приоритет.

[Инструменты авторизации и загрузки истории](src/tools/README.md). [История изменений 20 октября](docs/change-report-2026-10-20.md) описывает прежнюю версию; текущие правила приведены выше.
